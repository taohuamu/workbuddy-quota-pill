## 二、核心的一条：参数没有贯穿到底

D1 只是文档问题，D2 才触到实质：`--window` 改了，读数跟着变，文案却恒说「近 15 分钟」。
根因是 `forecast.decide()` 的返回值里没有窗口，而 `row_texts` 调用
`forecast.phrase(fc, brief=True)` 时也没传——于是落回默认 15。D3 又发现详情页标签是写死的
`"近 15 分钟"`，同一个病在第二个面上。

修法没有逐处打补丁，而是让**结果自带窗口**：`decide()` 把 `window_min` 写进返回字典，
`phrase()` 优先用它。这样所有「只拿到结果」的调用方（卡片、`--print`、技能版表格）
一次全部正确——这也是为什么这条改动要落在共用的 `forecast.py` 上。

D4 顺着这条线又发现两处：`phrase` 里用 `or` 取窗口，`window_min=0` 被当成假值回落；
负窗口直接进文案。改成显式 `is None` 判断，并在两个 CLI 入口把窗口夹到 ≥1。

## 四、未解决 / 建议后续

1. **`--print` 没有风险退出码**：技能版 `quota_report` 会因 `has_risk` 返回 1，桌面版不会。
   桌面是常驻 GUI，暂无脚本消费方，判为不做；若以后要接自动化，需先定语义。
2. **`--window` 没有上限**：任意正整数都能算，理论上 `--window 100000` 会把窗口拉到日志开头。
   未观察到坏效果，不设限。
3. **图片配图仍是 15 分钟口径**：`docs/images/` 三张图用默认参数生成，与 README 一致；
   若 README 以后要展示自定义窗口，需要重拍。
